# Google Play

The Android app is a Trusted Web Activity (TWA): a small native shell, generated by
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap), that opens `https://www.theshotcaller.online/`
full screen in the player's Chrome. The game itself is the website, so **every web release reaches Android players at
once**; a new Play build is needed only when the shell changes (icon, name, colours, package settings, a newer target
SDK).

## What the project already does

- `android/` is the Bubblewrap 1.25 project: package `online.theshotcaller.game`, launcher name *Shotcaller*,
  target SDK 36 (Google Play's requirement from 31 August 2026), min SDK 21, notifications delegated to Chrome.
  `android/twa-manifest.json` is the source; `npm run android:update` regenerates the Gradle files from it.
- The host is `www.theshotcaller.online`: the apex domain answers with a 308 redirect, and Android does not follow
  redirects when it checks Digital Asset Links.
- The site build emits `/.well-known/assetlinks.json` from the fingerprints in `android/twa-manifest.json`
  (`scripts/assetLinks.ts`). Until the Play app signing fingerprint is there, the app opens with Chrome's address bar.
- `/delete-account` explains account deletion in the game and by email, as the Data safety form requires; the privacy
  policy links to it.
- A friend's profile has **Report** beside **Block**, as the User Generated Content policy requires for chat. Reports
  land in `player_reports` and the support Telegram chat.
- The app opens `/?source=twa`, so analytics can tell Android players apart.

## Tools

- Node 24 (already used by the project).
- JDK 17 and the Android SDK command-line tools. On the first `npm run android:build`, Bubblewrap offers to download
  both into `~/.bubblewrap`; accepting means accepting the Android SDK licence.

## 1. Upload key (once)

```bash
keytool -genkeypair -v -keystore android/android.keystore -alias shotcaller -keyalg RSA -keysize 2048 -validity 10000
```

Keep `android/android.keystore` and its passwords out of the repository (`.gitignore` already does) and back them up.
With Play App Signing, Google holds the key that signs what players install; this upload key only proves uploads are
yours, and Google can reset it if it is lost.

## 2. Build

```bash
npm run android:build
```

Set `BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD` to skip the prompts. The build writes
`android/app-release-bundle.aab` (for Play) and `android/app-release-signed.apk` (for a phone). Both stay out of git.

## 3. Asset links

1. In Play Console, upload the first `.aab` to **Internal testing**; Play App Signing turns on with it.
2. **Test and release → App integrity → App signing**: copy the *App signing key certificate* SHA-256.
3. Add it, and the upload key's own fingerprint for local APKs:

   ```bash
   cd android
   npx @bubblewrap/cli@1.25.0 fingerprint add <PLAY SHA-256> --name=play
   keytool -list -v -keystore android.keystore -alias shotcaller
   npx @bubblewrap/cli@1.25.0 fingerprint add <UPLOAD SHA-256> --name=upload
   ```

4. Commit `android/twa-manifest.json` and deploy the site. Check that
   `https://www.theshotcaller.online/.well-known/assetlinks.json` lists both fingerprints, then open the app from the
   internal test: there must be no address bar.

## 4. A new build of the shell

Raise `appVersionCode` (and `appVersionName`) in `android/twa-manifest.json`, run `npm run android:update`, then
`npm run android:build` and upload the bundle. `tests/application/android.spec.ts` checks that the Gradle files match.

## 5. Store submission checklist

- **Account:** personal accounts created after 13 November 2023 must run a closed test with at least 12 testers for
  14 days in a row before applying for production. New personal accounts also complete identity verification.
- **App content:** privacy policy `https://www.theshotcaller.online/privacy`; no ads; target audience 16–17 and 18+
  (the privacy policy sets 16+); content rating questionnaire with in-game chat answered as *users can interact*.
- **Data safety:** see the draft below; account deletion URL `https://www.theshotcaller.online/delete-account`.
- **App access:** everything works without signing in; online features accept any email address through a one-time
  code, so reviewers need no test account.
- **Supabase:** apply `supabase/migrations/20261005200000_player_reports.sql` before the release goes out.
- **Listing:** 512×512 icon (`public/pwa-512x512.png`), a 1024×500 feature graphic, at least two phone screenshots.

### Data safety draft

Data leaves the device over HTTPS and players can delete it (in the game and at `/delete-account`). Processors that
work on our behalf (Supabase, Vercel, PostHog, Resend) do not count as sharing.

| Data type | Collected for | Optional |
| --- | --- | --- |
| Email address | Account management | Yes: guests play without an account |
| Name, photo (from Google sign-in) | App functionality | Yes |
| User IDs | App functionality, account management | Yes |
| Other in-app messages (chat) | App functionality | Yes |
| Other user-generated content (nickname, reports, support requests) | App functionality, account management | Yes |
| App interactions (page views; finished matches only with consent) | Analytics | Page views: no |
| Diagnostics, app performance (Vercel Speed Insights) | Analytics | No |

Check each answer against the privacy policy before submitting; the form is a legal statement.
